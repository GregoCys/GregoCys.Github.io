Conditional Execution & Flag Reconstruction

Traced branching logic in a Windows executable and reproduced the relevant data transformation in a standalone test program.

Windows Binary AnalysisCompleted interview exerciseThird-party challenge
Publication context. This article summarizes an independently completed technical interview exercise using original commentary. The challenge was provided by a third party; the exercise is not represented as my own product, a public vulnerability, or a commissioned professional engagement. Original company branding, challenge assets, flags, and step-by-step solution details have been omitted.

The problem

The assessment executable selected among multiple output paths based on a secondary parameter. Straight string searches did not explain the program’s displayed output, requiring a closer look at conditions and formatting logic.

Research methodology

  1. Established a static baseline with disassembly and decompiled control flow, focusing on the function with multiple output paths.
  2. Used runtime debugging to inspect branch conditions and compare observed execution with the decompiled logic.
  3. Wrote a small C test program to reconstruct the relevant output-building behavior outside the original executable.

Tools & techniques

GhidraIDAx32dbgC / VS Code

Result

The reconstructed logic produced the expected hidden output in the original assessment. The exercise demonstrated how static and dynamic analysis can complement one another when a code path is difficult to reach through normal interaction.

What I practiced

Control-flow reasoning, parameter tracing, x86 debugging, and translating decompiled logic into a reproducible C test.

Legacy ROM Reverse Engineering

Analyzed a Sega Genesis ROM, its short timer, and the execution path controlling the program's display.

Motorola 68000 / Game ROMCompleted interview exerciseThird-party challenge
Scope: I completed this as a technical interview exercise. I have omitted the original company's materials, challenge secrets, and step-by-step solution.

The problem

The supplied binary behaved as a console ROM rather than a normal operating-system executable. Under emulation it presented a brief timer and limited controller interaction, leaving the intended output inaccessible through normal inputs.

How I approached it

  1. Determined the file’s execution environment and used an emulator to establish baseline behavior.
  2. Used Ghidra to navigate ROM strings, routines, and Motorola 68000 control flow.
  3. Studied the timer and display pathways and tested a local modification to understand how alternative execution paths affect the output.

Tools and techniques

GhidraSega Genesis emulatorCyberChefLinux

Result

A modified local copy revealed the intended result in the emulator. The original document describes a successful demonstration, not a vulnerability in a production game.

What I learned

The important first step was recognizing the target architecture and running the ROM in the correct emulator. That made it possible to follow the timer and display code rather than treating the file as an ordinary executable.

CrackMe 01: validation reversal and one-byte patch.

A controlled Windows x64 reverse-engineering exercise. From input transformation and branch tracing to a verified minimal binary modification.

Windows PE32+ (x64)Ghidra / x64dbg / PowerShellOwned lab challenge
Read detailed case report →

Executive summary

The objective was to understand an activation-code validator and prove how a client-side decision could be modified. Static analysis exposed an eight-byte validation routine. Runtime debugging confirmed that a zero return value led to the locked path.

Technical evidence

Input transformation(input[i] XOR key[i]) + offset[i]
Recovered activation codeQ7M-42PX
Decision instructionTEST EAX,EAX / JNE unlocked
Modified file offset0x585
Original → patched opcode75 → EB
Changed bytes1

Verification

The patched executable reported [UNLOCKED] Feature enabled. for invalid input. Both files remained 3,584 bytes; a byte-for-byte comparison found one modified byte.

Interpretation & limitations

This demonstrates that a local authorization decision can be changed by someone controlling the client executable. It does not establish a remotely exploitable vulnerability in a third-party product.

Educational work performed on a purpose-built challenge binary. No unauthorized software or services were targeted.
